# 歌词灵动岛 · 项目计划书

> 版本 v1.0 ｜ 面向 LX Music 增强版（v2.12.5）｜ 目标平台 Windows / macOS / Linux
> 调研部分基于 GitHub 真实项目源码与官方文档，引用见文末；未核实项已单独标注。

---

## 一、项目背景与目标

### 1.1 为什么做

当前项目已具备**桌面歌词窗**，且已有「歌词条」模式（`desktopLyric.mode`），底层能力相当扎实：

| 已有能力 | 代码位置 |
|---|---|
| 无边框透明置顶窗 | `src/main/modules/winLyric/main.ts`（`frame:false, transparent:true, hasShadow:false`） |
| 任务栏歌词模式 | 同文件，`isTaskbarMode` 分支 + `setAlwaysOnTop(true,'screen-saver')` |
| 强制置顶轮询 | 同文件 `alwaysOnTopTools.startLoop()` |
| 鼠标穿透 | `setIgnoreMouseEvents` 已导出（`winLyric/main.ts:339`） |
| 全屏隐藏 / 暂停隐藏 | `desktopLyric.fullscreenHide` / `desktopLyric.pauseHide` |
| 音频可视化 | `desktopLyric.audioVisualization` + 4 种样式 |
| 字体/颜色/行距/延迟滚动/锁定 | `desktopLyric.style.*` 一整套 |

**缺的是「形态」**：现有歌词窗是**矩形面板**，交互是「显示/隐藏 + 拖动 + 锁定」。
灵动岛要的是**形态本身成为信息载体**——收起时是一条药丸、悬停时弹开成完整播放卡，切换状态带物理动效。

### 1.2 目标

1. **一个新的视图形态**（不改动、不破坏现有桌面歌词与歌词条，三者并存可切）。
2. **收起态极简**：屏幕上只占一条窄条，常态显示当前歌词 + 一个播放指示。
3. **展开态完整**：悬停/点击展开为封面 + 歌名 + 逐字歌词 + 进度 + 控制。
4. **全平台可用**：Windows 优先，macOS/Linux 降级可用（见风险章）。
5. **低打扰、低功耗**：非播放时不渲染，隐藏即停帧。

### 1.3 非目标（本期明确不做）

- 不做「注入任务栏、长在任务栏里」的任务栏歌词（那是另一条路线，见 §3.2）。
- 不做 AppBar 工作区占位（避免与用户最大化窗口行为冲突）。
- 不做 Spout2/推流输出。
- 不改动现有歌词渲染算法（逐字高亮逻辑复用现有 `core/lyric.ts`）。

## 二、竞品与开源案例调研结论

完整调研报告见 `动态岛调研-原始报告`（工作区 `dynamic-island-lyrics-research.md`）。这里只保留**对本项目有决策价值的结论**。

### 2.1 第一梯队：桌面歌词条 / 任务栏歌词

| 项目 | Star | 技术栈 | 对本项目的意义 |
|---|---|---|---|
| [Lyricify](https://github.com/WXRIW/Lyricify-App) | 7.3k | Windows | 形态矩阵最全（灵动岛/桌面/任务栏/舞台）。其[术语表](https://docs.lyricify.app/lyricify-fusion/terms/)几乎等于需求清单：妙控条、多行高亮、背景人声、呼吸点、单词发光 |
| [SPlayer](https://github.com/SPlayer-Dev/SPlayer)（原 imsyy） | 7.4k（已归档） | Vue3 + Electron + Rust | [PR #777](https://github.com/SPlayer-Dev/SPlayer/pull/777) 给出**任务栏空闲区定位**的完整可抄实现（Shell_TrayWnd → UIA bounding rect） |
| [BetterLyrics](https://github.com/jayfunc/BetterLyrics) | 2.2k | C#/WinUI3 | 设置项最完整；「工作区模式」「强制置顶(轮询)」「穿透但控制栏可点」「边缘羽化」值得逐条抄 |
| [TaskbarLyrics](https://github.com/ANYNC/TaskbarLyrics) | 236 | C#/WPF | **智能置顶**：全屏应用在前台时自动让位；并诚实承认系统界面（开始菜单）仍可能遮挡 |
| [TaskbarLyrics Light](https://github.com/sorawithcat/TaskbarLyrics) | 7 | WPF | 给出常驻歌词条的**性能预算**：内存 669MB→340MB |
| [eIsland](https://github.com/JNTMTMTM/eIsland) | 320 | Electron + React | **形态最接近本项目的对标**：`focusable:false` + 尺寸常量状态机 + 悬停延时收起 + 复位热键 |
| [Lyrics-Plus](https://github.com/afeibukaixin/Lyrics-Plus) | 50 | Tauri + Rust | 非 Electron 路线的对照样本 |

### 2.2 Web 组件：动画与状态机

**[cult-ui Dynamic Island](https://github.com/nolly-studio/cult-ui)（6.2k）是最推荐精读的实现**，[源码已通读](https://github.com/nolly-studio/cult-ui/blob/main/apps/www/registry/default/ui/dynamic-island.tsx)，7 条可直接借鉴：

1. **预设尺寸表而非测量 DOM**：14 种形态（`compact/large/ultra/massive`…）各给 `{width, aspectRatio, borderRadius}`，高度由 `aspectRatio × width` 反算 —— 避免每帧 `getBoundingClientRect` 造成的布局抖动。
2. **弹簧参数全局统一**：`stiffness 400 / damping 30`。
3. **圆角形变取巧**：动画期间 `clipPath: none`，`transitionEnd` 再套 squircle 路径 —— 绕开「连续曲率无法插值」。
4. **内容交叉淡出**：按 `size !== previousSize` 判定是否换形态，`AnimatePresence` 做 opacity/scale/blur 过渡。
5. `useWillChange()` 统一管理合成层提示（只在过渡期存在）。
6. **多步编排** `useScheduledAnimations([{size, delay}])` + reducer 队列 —— 做「先收窄再拉伸再展开」的 iOS 式分步。
7. 移动端把超宽形态钳到 350px。

**歌词渲染用 [AMLL](https://github.com/amll-dev/applemusic-like-lyrics)（2.1k），不要自己写** —— 它同时提供 React 与 Vue 绑定，逐字高亮/弹簧回弹/模糊渐隐都已成熟，与「岛的形状动画」正交。

### 2.3 两条任务栏路线的取舍（本项目建议选 B）

| 路线 | 做法 | 优点 | 代价 |
|---|---|---|---|
| A. 定位任务栏空闲区 | SPlayer：Shell_TrayWnd → ReBarWindow32 → MSTaskSwWClass → TrayNotifyWnd + UIA bounding rect | 真正"长在任务栏里" | 需原生模块；Win10/Win11 分叉；任务栏位置/居中/DPI/托盘增删全要跟 |
| **B. 独立悬浮条**（本项目选此） | 透明无边框窗 + `setAlwaysOnTop(true,'screen-saver')` + 位置由用户决定/自动吸附屏幕下沿 | 无原生依赖；跨平台一致；与现有 `winLyric` 架构同构，改动最小 | 无法真正嵌入任务栏；全屏应用可能遮挡（用智能置顶缓解） |

> 结论：**先做 B**，把形态与动效做扎实；若后续确需"嵌进任务栏"，A 作为独立里程碑（复用 SPlayer 的思路），不阻塞本期。

## 三、交互与状态设计

### 3.1 状态机（核心）

```
                 ┌──────────── 无播放 ────────────┐
                 │  空闲：完全隐藏（不渲染）        │
                 └────────────────────────────────┘
                              ▲ 开始播放
   ┌──────────────────────────────────────────────────────┐
   │                     COLLAPSED（收起态）               │
   │  药丸形：当前歌词单行（逐字高亮） + 播放指示 + 细进度  │
   └──────────────────────────────────────────────────────┘
        │ 悬停 120ms 防抖            │ 切歌事件
        ▼                            ▼
   ┌──────────────┐          ┌──────────────────┐
   │ EXPANDED     │          │ FLASH（闪一下）   │
   │ 完整播放卡   │          │ 歌名+歌手，1.2s  │
   └──────────────┘          └──────────────────┘
        │ 移出 900ms（大展开 1500ms）
        ▼ 回到 COLLAPSED
```

**形态尺寸预设**（借鉴 cult-ui 的预设表思路）：

| 形态 | 尺寸（DIP） | 圆角 | 内容 |
|---|---|---|---|
| `flash` | 260 × 44 | 22 | 歌名 - 歌手 |
| `collapsed` | 420 × 44 | 22 | 当前歌词 + 播放指示 + 进度细线 |
| `expanded` | 420 × 168 | 28 | 封面 96 + 歌名/歌手 + 3 行歌词 + 进度 + 控制 |
| `expandedLong` | 560 × 168 | 28 | 长歌名/长歌词自适应 |
| `notice` | 320 × 44 | 22 | 状态通知（换源中/加载失败） |

### 3.2 展开/收起时机（逐条定）

| 行为 | 规则 | 依据 |
|---|---|---|
| 悬停展开 | 进入后 **120ms** 防抖才展开（防鼠标划过误触） | eIsland |
| 移出收起 | `collapsed` 900ms / `expanded` **1500ms**（两档） | eIsland 的 `EXPAND_MOUSELEAVE_IDLE` / `MAX_*` |
| 空闲单击 | 展开（收起态） / 播放暂停（展开态播放键） | 通用 |
| 切歌 | `FLASH` 1.2s 后回收起态 | 灵动岛标志性动作 |
| 暂停 | `pauseHide` 开：渐隐（0–3000ms 可配）；关：保持 | 现有设置项沿用 |
| 无媒体 | `无播放`：完全隐藏（不渲染、不轮询） | 省电 |
| 全屏应用 | **让位**（默认开，可关） | [Lyricify FAQ](https://docs.lyricify.app/lyricify-fusion/faq/desktop-lyrics-disappear/) 的根因就是这个 |

### 3.3 内容优先级

**收起态（最多 1–2 行）**：
1. 当前歌词行（逐字高亮）— 最高优先
2. 下一行（可选双行，`collapsedLines: 1|2`）
3. 播放/暂停指示（一个小圆点或图标，不占位）
4. 极简进度（1px 细线贴在药丸底边，或环形微指示）

**展开态**：
封面（圆角方，可切圆/方）→ 歌名 + 歌手（可点跳搜索）→ 前后各 1~2 行歌词（当前行居中放大）→ 进度条（**悬停进度条预览该时间点歌词**，BetterLyrics 的加分项）→ 播放控制（上一首/播放/下一首 + 播放模式）→ 音量 → 右键菜单（锁定/隐藏/设置/复位位置）。

**降级规则**：
- 纯音乐 / 无歌词 / 匹配失败 → **显示实时频谱，不留空白**（TaskbarLyrics 两版都这么做，且默认开启）
- 歌词过长 → 行内横向滚动或省略号（可选）
- 封面缺失 → 显示主题色渐变块 + 应用图标

### 3.4 鼠标与穿透设计

原则：**默认穿透，但随时能收回来**。

| 场景 | 行为 |
|---|---|
| 锁定态（穿透） | `setIgnoreMouseEvents(true, { forward: true })`，鼠标进不来 —— 用全局快捷键/托盘解锁 |
| 解锁态 | 正常接收鼠标，可悬停展开、可点击控制 |
| 拖动 | **必须手动拖拽**（`mousedown` + `screen.getCursorScreenPoint()` + `setBounds`），**不能用 `app-region: drag`** |
| 吸附 | 阈值 16–24 DIP 吸附屏幕边缘；贴左边时展开方向镜像 |
| 复位 | 全局快捷键 + 右键菜单 + 托盘菜单三处入口 |

> ⚠️ **关键坑（已核实）**：`app-region: drag` 的官方行为是「draggable areas ignore all pointer events」，与「悬停展开」直接冲突。
> 而 `setIgnoreMouseEvents` 的 `forward` 选项是 **macOS/Windows 专属**，**Linux 上悬停切换穿透不成立**（Electron 有 [#54393](https://github.com/electron/electron/pull/54393)、[#51144](https://github.com/electron/electron/pull/51144) 两个修复 PR 说明这块历史上就不稳）。
> **因此：全局快捷键（显隐/锁定/复位）不是可选项，是必需品。**

### 3.5 智能置顶（默认策略）

```
if (前台窗口是全屏应用 && fullscreenHide 开着) → 隐藏（不计入"用户关闭"）
else if (alwaysOnTopLoop 开着) → 保持轮询强制置顶
else → setAlwaysOnTop(true, 'screen-saver')
```

> ⚠️ **文档与现实的矛盾（已核实）**：Electron 文档称 `pop-up-menu` 及以上在 Windows 上高于任务栏，但 [issue #38020](https://github.com/electron/electron/issues/38020) 与生产级应用 TaskbarLyrics 都表示 `screen-saver` **压不住任务栏/开始菜单**。
> **对策**：① 默认智能置顶（全屏让位）；② 提供「强制置顶（轮询）」开关（本项目已有 `alwaysOnTopTools.startLoop()` 可直接复用）；③ **`fullscreenHide` 必须是可关开关**。

## 四、技术方案（Electron）

### 4.1 窗口参数（本项目基线，直接复用现有 `winLyric` 实现）

```js
// src/main/modules/winLyric/main.ts 已有同款参数，新增 island 模式即可
new BrowserWindow({
  frame: false,
  transparent: true,
  hasShadow: false,
  skipTaskbar: true,
  resizable: false,          // 透明窗不要开 resizable（官方：可能让透明失效）
  alwaysOnTop: true,
  focusable: false,          // 关键：不抢焦点，才能不打断用户当前输入
  show: false,
})
win.setAlwaysOnTop(true, 'screen-saver')
```

> 已核实的透明窗 5 条硬限制（[Custom Window Styles](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)）：
> ① 透明区域**不能**点击穿透（透明 ≠ 穿透，[issue #1335](https://github.com/electron/electron/issues/1335)）；
> ② 透明窗**不可 resize**；③ `blur()` **无法模糊下方其他应用**（"毛玻璃看穿桌面"做不到）；
> ④ 开 DevTools 时不再透明；⑤ Windows 上不能最大化、macOS 无原生阴影。

### 4.2 多屏与 DPI

- `Display.bounds` 与 `workArea` **都是 DIP**，且 `workArea` 已排除任务栏 → **贴边吸附必须用 `workArea`**，否则会吸到任务栏底下。
- 持久化策略：**存「显示器身份 + 相对 workArea 的 DIP 偏移 + 贴边信息」**，不要只存绝对像素。
- 监听 `display-added / display-removed / display-metrics-changed`；若窗口与所有 `workArea` 都不相交 → 复位到主屏。
- 需要物理像素时用 `screenToDipPoint / dipToScreenPoint`（Windows/Linux 专属），**不要自己乘除 `scaleFactor`**（各屏不同会累积误差）。
- 已知 bug：[#51949](https://github.com/electron/electron/issues/51949)（混合 DPI 多屏移动后高度不一致）、[#52501](https://github.com/electron/electron/pull/52501)。

### 4.3 主窗 ↔ 岛 的通信协议

**铁律：传时间轴，不传逐帧位置。绝不 60fps 走 IPC。**

| 频道 | 方向 | 内容 | 频率 |
|---|---|---|---|
| `island:toggle` | 主→岛 | 显隐 | 事件 |
| `island:lyric` | 主→岛 | **整段歌词数组**（含逐字时间轴）+ `(mediaTime, performance.now())` 对 | 换歌/换词 |
| `island:progress` | 主→岛 | 播放位置、时长、播放状态 | 1Hz 或状态变化 |
| `island:metadata` | 主→岛 | 歌名/歌手/专辑/封面 URL | 换歌 |
| `island:state` | 主→岛 | 播放/暂停/加载/错误 | 事件 |
| `island:theme` | 主→岛 | 主题色（主进程用 `nativeTheme.shouldUseDarkColors` 统一分发） | 系统变化 |
| `island:notice` | 主→岛 | 状态通知（换源中/失败） | 事件 |
| **`island:request-data`** | **岛→主** | **反向拉全量数据** | 岛启动/热重载/托盘唤起 |

> **必须有反向 `request-data`**：岛窗可能晚创建、可能热重载、可能从托盘唤起，没有它就必然出现"岛是空的"。
> 高频流式数据（若将来做频谱）走 `MessageChannelMain`/`MessagePortMain`，不要用字符串频道。

**岛内本地插值**：
```js
// 主进程只推一次 (mediaTime0, perfNow0) + 歌词数组
// 岛内用 rAF 本地推进：mediaTime = mediaTime0 + (performance.now() - perfNow0) / 1000
// 暂停/seek 时主进程再推一次校正
```

### 4.4 性能与功耗

- **不要为了"歌词不断帧"无脑关 `backgroundThrottling`**：官方事实是「一旦某个 webContents 关掉它，整窗都会继续绘制换帧」。正确做法是**隐藏时直接 `win.hide()`**。
- 动画只用 `transform` / `opacity`；若坚持动 `width/height`（cult-ui 路线），用 spring + `will-change` 仅在过渡期存在。
- 空闲降帧：非播放时不跑 rAF；`collapsed` 态歌词整行变化时才重绘。
- 帧率上限可配（60/90/120），默认 60。
- 性能预算参照：常驻歌词条尽量控制在 **内存增量 < 60MB、空闲 CPU < 0.5%**。

### 4.5 动画方案（推荐组合）

| 用途 | 方案 | 理由 |
|---|---|---|
| **岛的形状/尺寸/圆角** | 预设尺寸表 + **CSS transition on width/height/border-radius**（`cubic-bezier` 或 `linear()` 弹簧）；若已有 Framer Motion 则用 `animate` + spring 400/30 | 尺寸与圆角天然同步；不引库也能做（Chromium 版本自控） |
| **内容交叉切换** | Vue `<Transition>` + opacity/scale/blur | 无需额外依赖 |
| **多步编排**（收窄→拉伸→展开） | 定时器队列 + 状态去重（`newSize !== size && newSize !== prevSize`） | 防快速反复悬停打架 |
| **逐字歌词进度** | rAF 本地插值（不用 transition） | 每帧标量，transition 不适合 |
| **频谱** | rAF + Canvas（复用现有可视化实现） | 已有 4 种样式 |

**明确不推荐**：View Transitions API 做悬停展开 —— Motion 官方列的硬伤是「不可打断（打断会先跳到终点）、动画期遮挡并阻止指针交互、性能更差」。
（若本项目后续想引 `motion-v`，其 Vue 版 layout 动画能力**未核实**，需先验证。）

## 五、设置项设计

复用现有 `desktopLyric.*` 体系，新增 `island.*` 命名空间（与桌面歌词并列，互不影响）：

**形态与位置**
- `island.enable` 启用歌词灵动岛
- `island.targetDisplay` 目标显示器：主屏 / 光标所在屏 / 指定
- `island.dock` 停靠：上 / 下 / 左 / 右 / 自由
- `island.offsetX` / `island.offsetY` 相对 workArea 偏移（DIP）
- `island.resetPosition` 一键复位（含全局快捷键）

**置顶与穿透**
- `island.alwaysOnTop` 置顶
- `island.alwaysOnTopLoop` 强制置顶（轮询）— 复用现有 `alwaysOnTopTools`
- `island.fullscreenHide` 全屏应用时让位（**必须可关**）
- `island.lock` 锁定（穿透）
- `island.unlockHotkey` 解锁全局快捷键（默认 `Ctrl+Alt+L`）
- `island.keepControlsInteractive` 穿透时保持控制栏可点（Windows/macOS）

**显示与隐藏**
- `island.pauseHide` 暂停时隐藏 + `island.fadeDelay` 渐隐延迟 0–3000ms
- `island.emptyHide` 无媒体时隐藏
- `island.collapsedLines` 收起态行数 1|2
- `island.hoverExpandDelay` 悬停展开延时（默认 120ms）
- `island.mouseleaveCollapseDelay` 移出收起延时（默认 900ms）
- `island.expandMouseleaveIdle` 大展开态收起延时（默认 1500ms）

**外观**
- `island.theme` 浅 / 深 / 跟随系统
- `island.colorMode` 适应封面主题色 / 适应主题色 / 固定色
- `island.backgroundOpacity` 背景不透明度
- `island.feather` 边缘羽化（四边独立 0–100%）
- `island.cornerStyle` 圆角 / 连续曲率（squircle）
- `island.coverShape` 封面形状：方 / 圆角方 / 圆
- `island.font.*` 字体/字号/字重/描边/阴影（复用现有 `desktopLyric.style.*` 结构）
- `island.lyricEffect` 歌词切换动效：上滑 / 淡入淡出 / 紧凑滑动 / 无
- `island.showSpectrumWhenNoLyric` 无歌词时显示频谱（默认开）+ 频谱样式

**内容**
- `island.showTranslation` / `island.showRoma` 翻译 / 音译（复用现有开关）
- `island.hoverProgressPreview` 悬停进度条预览该时间点歌词（默认开）

**快捷键（全部走全局快捷键，因为岛窗不可聚焦）**
- 显隐岛 / 锁定切换 / 复位位置 / 播放暂停 / 上一首 / 下一首 / 开关桌面歌词

## 七、风险评估

| 风险 | 等级 | 影响 | 对策 |
|---|---|---|---|
| **Linux 悬停切换穿透不成立** | 高 | Linux 用户无法「悬停展开」 | ① Linux 默认**不穿透**（可点击），隐藏用全局快捷键；② 文档明确说明；③ 提供托盘/快捷键作为唯一入口 |
| **`screen-saver` 压不住任务栏/开始菜单** | 中 | 全屏应用或开始菜单打开时岛被遮 | 默认智能置顶 + 可选轮询强制置顶 + 全屏让位可关 |
| **透明窗限制**（不能 resize / 无背景模糊） | 中 | 用户期望"毛玻璃"会失望 | 用纯色/渐变半透明背景替代真实模糊；尺寸变化用代码 `setBounds` 而非用户拖拽边缘 |
| **`app-region: drag` 与悬停冲突** | 中 | 整块可拖就收不到 hover | 手动拖拽实现（`getCursorScreenPoint` + `setBounds`），只在拖动期间接管 |
| **混合 DPI 多屏错位** | 中 | 副屏上岛跑到屏幕外 | 存显示器身份 + 相对 workArea 偏移；监听 display 事件自动复位；提供复位热键 |
| **高频 IPC 卡顿** | 中 | 动画掉帧 | 传时间轴 + 岛内 rAF 插值；绝不逐帧 IPC |
| **常驻窗口耗电** | 中 | 笔记本续航下降 | 隐藏即 `win.hide()`；不关 `backgroundThrottling`；帧率上限可配 |
| **与现有桌面歌词冲突** | 低 | 两个歌词窗同屏 | 三种形态（常规/歌词条/灵动岛）**互斥单选**，切换时销毁另一个 |
