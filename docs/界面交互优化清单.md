# LX Music 增强版 · 界面交互与操作优化清单

> 基于当前源码（v2.12.5，`main` 分支）逐文件通读整理，每条都标注了涉及文件与位置，可直接当排期清单用。
> 项目基线：10 个设置分组、121 行快捷键定义、详情页三态视图（歌词/队列/评论）、桌面歌词含「歌词条」模式。

## 0. 总体判断

当前界面的**视觉**已经打磨得比较充分（Luminous Harmonic 玻璃流光、封面双取色、逐字/逐行高亮、环形频谱），
但**交互层面**仍有几类系统性缺口：

| 类别 | 核心问题 |
|---|---|
| A. 快捷键覆盖不全 | 大量高频操作没有快捷键，且不支持自定义组合 |
| B. 危险操作无护栏 | 清缓存/清列表/删歌单等不可逆操作缺少明确确认与撤销 |
| C. 状态可见性不足 | 加载/失败/换源/降级取色等状态只在播放栏小字提示，无处查因 |
| D. 鼠标操作效率 | 列表批量操作、右键菜单、拖拽排序的能力与发现性都偏弱 |
| E. 无障碍与键盘可达 | 大量节点无 `aria-*`、无 `tabindex`，纯键盘无法完成播放操作 |
| F. 反馈及时性 | 多处点击后「无即时反馈」（切音源、切音质、加歌单） |

## 1. 播放与详情页交互

### 1.1 P0 · 进度条可拖拽精度与预览
- **现状**：`common-progress-bar` 支持拖拽与波浪样式（`PlayDetail/components/`），但拖动时**不显示目标时间浮标**，也不显示目标位置的歌词。
- **优化**：
  1. 拖动/悬停时在光标上方显示浮标（`mm:ss` + 若该位置有歌词则显示该行）。
  2. 按住 `Shift` 微调（±1s）；单击进度条跳转时保留「按住拖动」的判定阈值，避免误触。
  3. 键盘：进度条 `tabindex="0"` + `←/→` 5s、`Shift+←/→` 1s、`Home/End` 首尾。
- **涉及**：`src/renderer/components/layout/PlayDetail/PlayBar.vue`、`src/renderer/utils/compositions/usePlayProgress.ts`

### 1.2 P0 · 播放控制键盘可达
- **现状**：播放/上一首/下一首在 `PlayBar.vue` 里是 `<div @click>`（第 26/29/35 行），**不是 button，无 tabindex，无键盘触发**。
- **优化**：改为 `<button type="button">`（或补 `role="button" tabindex="0" @keydown.enter/space`），加 `aria-label`（现已部分有）。这是**无障碍硬伤**，也是「键盘党」最直接的痛点。
- **验收**：拔掉鼠标，仅用 `Tab`/`Enter` 能完成播放/暂停/切歌/调音量。

### 1.3 P1 · 详情页三态视图的可知性
- **现状**：歌词/队列/评论三态靠工具栏图标切换（`ControlBtns.vue`），**图标无文字提示、无快捷键**。
- **优化**：① 加 `Tab` 循环三态快捷键（或在现有快捷键体系里新增）；② `Esc` 目前退出详情页——建议改为「评论/队列态先返回歌词态，再按一次才退出」；③ 切换到评论/队列时保留滚动位置。
- **涉及**：`PlayDetail/detailViewState.js`、`ControlBtns.vue`

### 1.4 P1 · 歌词交互增强
- **现状**：已支持点击歌词跳转、`Ctrl+滚轮` 缩放、右键菜单（`LyricMenu.vue`）。
- **优化**：
  1. **双击歌词** → 复制该行（现有「允许选中歌词文本」是全局开关，双击复制更顺手）。
  2. 当前行**拖拽调整偏移**（左右拖 = 调 `offset`），比菜单里 ±10ms 更直观。
  3. 长歌词横向溢出时提供**行内滚动而非截断**（现由 `desktopLyric.style.ellipsis` 控制桌面歌词，详情页也应可选）。
  4. 歌词搜索/换源入口：右键菜单加「搜索这句歌词」「从其他源重取歌词」。

### 1.5 P2 · 封面区域的交互
- **现状**：封面点击进入/退出详情页，右键有定位当前播放（`player__pic_tip`）。
- **优化**：① 封面上滚轮 = 音量（可选，默认关）；② 拖拽封面到歌单/收藏 = 快速收藏（与列表拖拽一致的心智）；③ 双击封面 = 播放/暂停。

## 2. 列表与歌单操作效率

### 2.1 P0 · 多选与批量操作
- **现状**：`OnlineList/index.vue` 与 `songList/` 支持部分批量（`selectedList`），但**全选/反选/区间选择（Shift 点选）**缺失或未被发现。
- **优化**：
  1. `Ctrl+A` 全选当前列表可见项；`Shift+点击` 区间选择；`Esc` 清除选择。
  2. 批量操作条**固定显示在列表底部**（现在依赖右键/顶部按钮，发现性差），并实时显示「已选 N 首」。
  3. 批量下载/收藏/加入歌单/移入歌单 四个高频动作放进该条。

### 2.2 P1 · 右键菜单分层过长
- **现状**：单曲右键菜单项较多（播放/稍后播放/收藏/不喜欢/下载/换源/复制名/查看详情/移除/定位…），平铺导致找项慢。
- **优化**：分为「播放相关 / 收藏与标记 / 文件与信息」三组，组间加分隔线；把「换源」提升为一级项（现在藏在子项）。

### 2.3 P1 · 拖拽排序的可发现性
- **现状**：歌单内排序需通过右键「调整位置」弹窗输入序号（`list_sort_modal`、`music_sort__input_tip`）。
- **优化**：保留现有弹窗，但**再加上直接拖拽**（HTML5 draggable 或 `Sortable` 思路），并在列表头显示拖拽手柄 `⋮⋮`。

### 2.4 P2 · 列表内搜索
- **现状**：已有 `list__search_tip`（名称/歌手/专辑）。
- **优化**：① 高亮匹配片段；② 支持 `/` 键唤起搜索框；③ 搜索结果内 「仅显示匹配项」与「滚动定位到匹配项」两种模式可选。

### 2.5 P2 · 列表空态与失败态
- **现状**：空态文案为 `no_item: "Nothing's here..."`、失败为 `list__load_failed`。
- **优化**：失败态给**可执行按钮**（重试 / 检查音源 / 打开设置）；空态给引导（去搜索 / 导入歌单 / 添加本地歌曲）。

## 3. 搜索体验

### 3.1 P1 · 搜索即时性与历史
- **现状**：`Search` 视图有热搜与历史（`setting__search_hot`、`history_*` 文案齐全）。
- **优化**：
  1. 输入**防抖 300ms** 的即时提示（下拉显示历史/热搜匹配），回车才真正搜索。
  2. 历史项支持**固定（pin）**，常用搜索不被冲掉。
  3. `↑/↓` 在提示列表内移动、`Tab` 补全、`Esc` 关闭。

### 3.2 P1 · 搜索结果排序与来源标识
- **优化**：结果区顶部加「按来源分组 / 按音质排序 / 只看无损」三个快捷筛选；每行显示音源标签与音质标签（已有 `tag__lossless` 等标签体系，可直接复用）。

### 3.3 P2 · 搜索结果与播放的联动
- **优化**：搜索结果行加「稍后播放」与「直接试听」两个 hover 按钮（不必进详情页）。

## 4. 设置页交互

### 4.1 P1 · 设置项改动即时生效与可撤销
- **现状**：多数项即时生效（好），但**没有「已修改」提示，也没有单项恢复默认**。
- **优化**：① 每项右侧 hover 出现「↺ 恢复默认」；② 修改后在设置页顶部出现「已更改 N 项 / 全部恢复」轻提示条；③ 危险项（缓存清理、数据同步覆盖）加二次确认 + 明确影响范围。

### 4.2 P1 · 设置搜索的定位体验
- **现状**：新分组方案（10 组）已实现分类 + `searchPrefixes` 定位。
- **优化**：搜索命中后**高亮命中项 1.5s**（现在只是滚动定位），并在结果旁显示所属分组面包屑。

### 4.3 P2 · 数值项改为滑块 + 数字输入
- **优化**：像 `player.songTransition` 那样的分段按钮很好；但超时/阈值类（本项目刚新增的换源时限 3 项）已用滑块 + 实时数值，建议**统一全部数值型设置**为「滑块 + 可直接输入的数值框」。

### 4.4 P2 · 设置导入导出粒度
- **优化**：支持「仅导出本组设置」（如只导出桌面歌词配置），便于分享与排障。

## 5. 状态反馈与可观测性

### 5.1 P0 · 播放失败的可查因
- **现状**：取 URL/换源/音频加载失败都只写一行状态文本（`PlayBar.vue` 的 `.getStatus`，11px 浮在进度条上方），失败后**无法回看尝试过哪些音源、各自错在哪**。
- **优化**（与本次换源规则改动配套）：
  1. 状态文本区域支持**点击展开**「本次播放诊断」浮层：列出尝试的音源顺序、每个源的耗时与结果、最终判定。
  2. 诊断浮层提供「复制诊断信息」按钮（排障提 issue 直接用）。
  3. 连续失败停止自动切歌时，给**「继续尝试」按钮**而非纯文本。
- **涉及**：`src/renderer/core/music/utils.ts`（本次已加 `[换源] xxx 失败(Nms 时限)` 日志）、`play/action.ts`、`PlayBar.vue`

### 5.2 P1 · 音源状态可视化
- **优化**：设置 → 音乐接口 里为每个音源显示**近 10 次成功率/平均耗时**（内存内统计即可），用户能自己判断该用哪个源。

### 5.3 P1 · 加载态与骨架屏一致性
- **现状**：评论有骨架屏（近期新增），列表/搜索结果仍是 spinner 或纯文本。
- **优化**：统一为骨架屏；超过 3s 的加载追加「仍在加载…（已 Ns）」并给「取消」。

## 6. 窗口与系统集成

### 6.1 P1 · 迷你模式
- **优化**：新增「迷你播放器」窗口（封面 + 歌名 + 播放控制，约 360×120），可从托盘/快捷键切换。这是同类播放器（AlgerMusicPlayer 有 mini 模式）的高频诉求。

### 6.2 P1 · 托盘菜单信息量
- **现状**：托盘菜单已有播放控制/歌词开关。
- **优化**：菜单顶部显示**当前歌曲「歌名 - 歌手」**（不可点），并把「播放模式」做成一格循环切换项。

### 6.3 P2 · 多显示器行为
- **优化**：记住「上次关闭时所在显示器」，并在该显示器不在了的时候回落到主屏；桌面歌词已有 `isLockScreen`（不拖出主屏），详情页/主窗也应有一致的回落策略。

### 6.4 P2 · 任务栏与缩略图
- **现状**：有 `player.isShowTaskProgess`（任务栏进度）与缩略图按钮（`winMain/utils.ts` 的 `collect/prev/play/next`）。
- **优化**：缩略图按钮补上**播放模式**与**音量**两个；进度条配色跟随主题。

## 7. 无障碍与键盘（系统性）

| 项 | 现状 | 建议 |
|---|---|---|
| 可聚焦控件 | 播放栏按钮是 `div` | 全部改 `<button>` 或补 `role`+`tabindex`+键盘事件 |
| 焦点样式 | 多数依赖默认 | 统一 `:focus-visible` 描边（主题色，2px） |
| 焦点顺序 | 未规划 | 播放栏 → 侧栏 → 内容区，`Tab` 顺序与视觉一致 |
| `aria-label` | 部分有（`aria-label` 已见于多处） | 补齐图标按钮；装饰性 svg 加 `aria-hidden="true"`（已有部分） |
| 动效 | 已有 `prefers-reduced-motion` 处理（`PlayBar.vue` 尾部） | 扩展到详情页流光/封面旋转/频谱 |
| 对比度 | 封面取色模式已做亮度钳制 | 抽查最深/最亮封面色下的 11px 小字（`.getStatus`、时间标签） |

## 8. 快捷键盘图（建议新增）

现有 121 行定义覆盖播放/歌词/窗口等。建议补充：

| 键 | 功能 | 理由 |
|---|---|---|
| `Ctrl+F` / `/` | 聚焦当前列表/搜索框 | 通用习惯 |
| `Ctrl+A` | 全选列表项 | 批量操作 |
| `Tab`（详情页内） | 循环 歌词/队列/评论 | 三态切换 |
| `Esc` | 逐层返回（评论→歌词→退出详情） | 符合层级直觉 |
| `Ctrl+Shift+S` | 手动换源（重取当前歌 URL） | 失败时的第一反应 |
| `Ctrl+Shift+D` | 开关桌面歌词 | 高频 |
| `Ctrl+Shift+I` | 打开播放诊断浮层 | 排障 |
| `Shift+←/→` | 进度 ±1s | 精调 |
| `Ctrl+↑/↓` | 音量 ±5% | 精调 |
| `M` | 静音切换 | 通用 |

## 10. 可量化验收口径

1. **纯键盘完成率**：不碰鼠标完成「搜索→播放→切歌→收藏→切详情→切视图→调音量」7 步 = 100%。
2. **失败可诊断率**：任意播放失败都能在 1 次点击内看到「试过哪些源 + 各自结果」。
3. **批量操作步数**：批量下载 20 首从「20 次右键菜单」降到「选中 + 1 次点击」。
4. **设置可回退**：任一项设置可在 1 次点击内恢复默认。
5. **无鼠标发现性**：所有图标按钮都有文字提示（tooltip/aria-label 覆盖 100%）。
